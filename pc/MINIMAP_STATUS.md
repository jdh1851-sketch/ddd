## 사용자 캡처에서 육안으로 확인한 내용

- 빙고: 3×3 원형 칸, 왼쪽 위 초록 별, 왼쪽 가운데 빨간 X. 하단 `X 6.02, Y 367.53`.
- 투창: `투창병·불`, `정답·불`, 주술사 이름표, 하단 `X -1.88, Y 162.35`.
- 이름표와 표식이 겹친다. 한 장의 정지 화면으로 내 투창 대상 여부, 이동 방향, 도착 또는 기믹 성공은 확인할 수 없다.
- 하늘색 O가 찍힌 명확한 표본은 아직 없다. 빈 원을 O라고 간주하지 않는다.

이 캡처들은 채팅 이미지로 육안 확인했다. 로컬 이미지 파일이 없어 실제 캡처를 OCR 엔진에 넣어 회귀 검증한 상태는 아니다. 합성 표본 테스트를 실제 캡처 인식 성공으로 보고하지 않는다.

## 데이터 연동 조사

사용자가 제시한 Npcap, SharpPcap/PacketDotNet, TargetPort, EntityMapFollowSelf 정보는 사용자 관찰 기록이다. 이 환경에 모비레이 실행 파일이나 설정 원본은 없다. 이전 ZIP 첨부는 32MiB 전송 한도로 가져오지 못했다. 공개 검색에서도 EntityMap 좌표 출력 API를 입증하는 문서는 확보하지 못했다. 따라서 **지원 API가 없다고 확정하지도, WebSocket을 좌표 API라고 가정하지도 않았다.** 현재 구현은 화면 인식이며 모비레이 파일, 설정, 포트, 패킷을 읽거나 변경하지 않는다.

## 구현 범위와 사용

- 세 번째 ‘미니맵 관찰’ 탭에서 ‘캡처 이미지 열기’로 이미지를 분석하거나 F8로 제목이 정확히 `좌표 미니맵`인 창 하나를 관찰한다. 모비레이 화면에 겹치지 않도록 매크로 창을 배치한다.
- F8 시작/일시정지, F9 즉시정지. 탭 전환, 창 위치/크기 변경, 인식 지연 시 이전 표시를 폐기한다. 창 닫힘·최소화·가림을 감지하면 관찰 중단한다.
- 한국어 OCR의 글자 위치와 점수로 `투창병·속성`과 `정답·속성`의 유일한 일치를 검사한다. 결과는 **이름표 후보 위치**이며 정확한 바닥 목표점이 아니다. OCR이 겹친 글자를 읽지 못하면 추측하지 않는다.
- 노란 삼각형과 가까운 `나:` 이름표가 유일하게 함께 인식되어야 내 위치 후보를 표시한다. 다른 유저의 하늘색 삼각형으로 대체하지 않는다.
- 하단 X/Y는 부호와 소수점을 보존해 읽는다. 화면 픽셀을 게임 좌표로 환산하지 않는다.
- 현재 프레임에서 원형 칸 9개가 맞는 격자를 찾고, 밝은 별+초록 테두리, 밝은 X+빨간 테두리를 후보로 표시한다. 가려진 격자는 이전 칸 위치로 채우지 않는다. O 인식은 표본 검증 전까지 보류한다.
- 초록 별의 추천 계산식과 O 확정 조건은 구현하지 않는다. 별이 사라지는 것을 성공으로 처리하지 않는다.
- 점수는 OCR/기하 근거의 휴리스틱 수치이며 실제 성공 확률이 아니다. 세 번 연속 관찰도 실제 기믹 성공이 아니다.
- 관찰 탭은 게임 입력 함수로 진입하기 전에 반환한다. 관찰 모듈에는 키보드·마우스 입력 기능이 없다. 로딩·사망·좌표 정지 감지에 의존하는 자동 이동도 아직 없다.

## 검증 및 제한

Linux 자동 검사: 전체 36개 통과. 기존 낚시/비동기 검사와 함께 속성 충돌/중복·낮은 OCR 점수·음수 좌표·다른 유저 구분·격자 가림·범위 원의 별 오인 방지·빨간 X와 테두리 구분·표식 변경 시 안정성 초기화·입력 경로 분리를 검사했다. 합성 표본 기반이며 실제 캡처 OCR 정확도나 Windows 게임 동작을 입증하지 않는다.

실제 모비레이 창 캡처와 게임 입력 검증은 이 Linux 환경에서 수행하지 못했다. Git 명령의 별도 연결로 시험판 브랜치를 올리고 GitHub Actions의 Windows EXE 빌드·독립 실행 검사를 진행한다. 최초 Windows 검사에서는 테스트 파일의 기본 인코딩이 CP1252여서 실패했고, 테스트의 소스 읽기를 UTF-8로 명시해 수정했다. 빌드 결과는 해당 브랜치의 Actions와 pc-minimap-observe-build.* 사전 릴리스에서 확인한다. EXE는 UI/OCR 초기화 검사를 통과한 경우에만 게시하며 이것이 실제 게임 인식 검증을 뜻하지 않는다.

## 다음 단계의 검증 기준

1. 실제 미니맵 이미지로 OCR과 표식 후보를 비교하고 오인식·가림·겹침을 검증한다. 하늘색 O 표본을 확보하면 후보 인식을 추가한다.
2. 게임 활성 상태에서 사용자가 짧게 방향키를 누른 전후의 X/Y와 카메라 방향을 기록한다. 축 대응과 카메라 회전 영향을 확인한 뒤 제한 시간·좌표 정지·근접 감속·오차 범위를 갖는 이동 보정을 별도 연결한다. `EntityMapFollowSelf=true`이므로 화면의 내 삼각형이 고정되어 보일 수 있으며 화면 픽셀 변화만으로 이동 성공을 판단하지 않는다.
3. 투창 후 추가 처치가 필요한지, 발판 O 확정 조건, 본인 대상 여부, 파티원 없이 가능한 조건을 실제 장면으로 확인한다. 성공 증거가 확보되기 전 다음 기믹으로 자동 전환하지 않는다.

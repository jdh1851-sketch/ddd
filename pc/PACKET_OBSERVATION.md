# 투창 패킷 관찰 시험판 0.10.4

기존 OCR 관찰 로그에서 좌표 합의는 28/29회였지만 번개 정답 표시는 색상 제한 때문에 인식되지 않았습니다. 이 버전은 화면 인식을 확장하는 대신 **현재 게임 통신을 수신 전용으로 기록해 직접 데이터 연동을 검증하는 도구**를 추가합니다. 좌표·개체 ID·속성을 해석하는 기능과 게임 이동/공격은 아직 연결하지 않았습니다.

## 사용

1. 모비레이가 동작하는 기존 PC에서 새 EXE를 별도로 실행합니다. 기존 Npcap을 사용하며 모비레이 실행 파일·설정은 수정하지 않습니다.
2. 게임의 1번 방 투창병 구간에 들어간 뒤 프로그램의 **패킷 기록** 탭에서 F8을 누릅니다.
3. 평소처럼 기믹을 수행합니다. 최대 60초 또는 PCAP 총 12MiB까지 기록하며 F8/F9로 중지할 수 있습니다. 창을 가려도 패킷 기록에는 영향이 없습니다.
4. **패킷 ZIP 저장**을 눌러 저장된 ZIP을 채팅에 첨부합니다. 수신 수가 0이거나 오류가 나도 ZIP의 진단 메타데이터로 원인을 확인할 수 있습니다.

게임 창의 PID와 Windows의 실제 TCP 연결 목록을 대조하여 16000번을 사용하는 연결을 선택합니다. 현재 TCP만 지원하며 UDP를 지원한다고 가정하지 않습니다. 게임 창 또는 해당 연결을 찾지 못하면 기록하지 않습니다. 연결 목록이 바뀌면 중단하므로 로딩 이전이 아니라 해당 방 안에서 시작합니다.

## 기록 범위

- 기존 Npcap의 수신 API에서 무차별 수신을 끈 상태(promiscuous=0)로 기록합니다. 송신·재전송·패킷 주입 API는 사용하지 않습니다.
- 게임 PID에서 확인한 IP·포트 쌍만 BPF로 필터링합니다. 다시 TCP 헤더를 확인한 패킷만 PCAP에 기록합니다. 게임의 애플리케이션 메시지 내용은 아직 해석하지 않습니다.
- 활성 장치 최대 16개에서 기록합니다. 동일 통신이 여러 장치에 중복 관찰될 수 있으므로 장치별 PCAP과 통계를 보존합니다. 수신 개수는 게임 메시지나 좌표 갱신 횟수가 아닙니다.
- 파일은 실행 폴더의 packet_logs/실행ID 아래에 저장됩니다. ZIP에는 정해진 metadata.json과 장치별 PCAP만 포함합니다. 자동 전송·모비레이 설정 수집·전체 화면 캡처는 없습니다.
- PCAP은 게임 통신 원문이므로 IP 주소 및 계정/개체 정보가 포함될 수 있습니다. ZIP 저장과 첨부는 사용자가 직접 합니다.

## 확인된 근거와 제한

[모비레이 공식 홈페이지](https://mobilay.kr/)에는 Npcap과 미니맵 기능이 안내되어 있지만, 조사한 공개 페이지에서 실시간 좌표 출력 API나 WebSocket 규격은 확인하지 못했습니다. 이것은 해당 기능이 없다는 증명이 아닙니다.

[제작자 기능 설명](https://gall.dcinside.com/mgallery/board/view/?id=enban&no=1186490)에는 물길의 위치 안내와 테로사 빙고 추천 계산이 설명되어 있습니다. 따라서 정답 별이 패킷에서 완성된 형태로 전달된다고 가정하지 않습니다. 공개된 과거 모바일 전투 파서는 현재 게임 버전과 맞는지 확인하지 못했으며 코드를 가져오지 않았습니다.

수신 구현은 [Npcap 공식 API 문서](https://npcap.com/guide/wpcap/pcap.html)를 기준으로 작성했습니다. 단위 검사와 단일 EXE 검사는 가짜 수신 API의 합성 TCP 데이터를 이용해 필터·정지·용량 제한·PCAP/ZIP을 확인합니다. 실제 사용자 PC의 Npcap 장치 수신과 게임 좌표 해석 검증은 별도입니다.

다음 단계는 받은 PCAP의 TCP 재조립과 메시지 구조를 확인하고, 실제 움직임과 좌표 후보를 대조하는 것입니다. 아직 검증되지 않은 공개 패킷 번호나 필드를 이동 판단에 사용하지 않습니다.

# 끌림 매크로 — Android 개발 채팅에 전달할 최신 확정 내용

기준: 2026-10-31, PC v0.12. 이 문서는 PC 개발 채팅에서 사용자가 확정한 규칙과 관측 결과다. 이전 v0.9 자료와 충돌하면 아래 최신 규칙을 우선한다. 현재 Android 채팅의 작업·코드를 지우거나 무조건 PC 구조로 교체하지 말고, 기존 구현에 해당 규칙을 병합한다.

## 1. 목적과 범위

마비노기 모바일 어비스 입장·자동전투·클리어·재입장을 Android 단독 앱으로 처리하려는 목적. 전투는 게임 자체 자동전투로 클리어한다. 던전, 난이도, 우연한 만남, 파티 구성은 사용자가 먼저 설정한다. 앱이 임의로 변경하지 않는다. 낚시는 이후 단계로 미완성이다.

PC 버전이 동작한다고 Android 화면 캡처/터치도 동작한다고 단정하지 않는다. 모바일 기종·Android 버전·게임 해상도·UI 배율은 이 PC 채팅에서 받지 않았다. 다른 채팅에서 받은 값이 있다면 그 값을 사용하고 없다면 확인한다. 모바일 게임 화면 및 실제 터치 검증 자료도 별도로 확보해야 한다.

## 2. 가장 중요한 최신 변경: 파티별 재입장

| 사용자가 선택한 고정 파티 | 결과 화면 이후 |
| --- | --- |
| 1인 | 다시 하기 |
| 2~3인 | 다른 던전 가기 → 지정한 동일 던전 선택 → 입장하기 |
| 4인 파티장 | 다시 하기 |
| 4인 파티원 | 파티장의 재입장 요청 대기 → 준비 완료만 입력 |

- 사용자는 1인은 기존 다시 하기를 유지한다고 명시했다.
- 고정 파티 인원과 4인 역할은 직접 선택한다. 우연한 만남 후 4명으로 표시되는 것은 고정 4인 파티 증거가 아니다. 자동 인원 판별을 가정하지 말 것.
- 4인 파티원은 입장하기/다시 하기를 누르지 않는다. 준비 완료는 누르고, 준비 취소는 절대로 누르지 않는다.
- 2~3인 경로에서 '다른 던전 가기'를 누른 뒤 목록에서 같은 던전을 다시 선택한다. 아무 던전이나 선택하지 않는다.
- 현재 PC 대상 목록: 허상의 정박지, 광기의 동굴, 흩어진 물길. 기본은 허상의 정박지. 선택 대상은 실행 전에 지정한다.
- 4인 역할 선택은 1인/2~3인에서 사용하지 않는다. PC 기본값: 1인, 역할 파티장, 던전 허상의 정박지.
- 2~3인 모드의 별도 파티원 역할 분기는 PC에 없다. 사용자 요청은 4인 파티원의 준비 완료 처리만 명시했다. 2~3인 파티원까지 임의로 역할 규칙을 확대하지 말고 실제 흐름이 다르면 확인한다.

## 3. 공통 화면 흐름

입장하기 또는 준비 완료 → 필요 시 도전하기 확인창 → 매칭·로딩 → 던전 초입 나침반 → 자동전투 → 필요 시 장면 넘기기 → '화면을 터치해 주세요' → 결과 화면 → 위 파티별 경로.

- 인원 부족 확인창: '어비스에 도전하시겠습니까?' 제목과 '도전하기' 버튼을 함께 감지할 때만 처리. 다른 도전 버튼에 오입력하지 않는다.
- 준비 취소가 보이면 이미 준비한 상태다. 입력 없이 기다린다.
- 장면 넘기기는 연출이 나타날 때 처리한다. 마지막 클리어 터치는 문구를 보고 화면 중앙을 터치한다.
- 다시 하기 뒤에는 입장 선택 화면을 거치지 않고 매칭/카운트다운/로딩으로 바로 이어질 수 있다.
- 던전 모집·초대·수락, 난이도 변경, 파티원 교체, 재접속, 실패 복구는 PC에서 자동 처리하지 않는다.

## 4. 반드시 유지할 버그 수정: 중간 시작 복구

이전 PC는 나침반을 눌러야만 battle로 바뀌는 구조였다. 전투 중 켜거나 재개했을 때 queue로 남아 브레이크6, 장면 넘기기, 클리어 터치, 다시 하기를 모두 놓쳤다. 실제 영상에서 점수 0.89/0.94/0.95로 인식해도 행동하지 않는 문제가 확인됐다.

v0.11 이후에는 입력 이력보다 현재 화면의 명확한 증거로 단계를 복구한다. 이미 전투·연출·결과 화면이면 해당 화면부터 이어간다. 초기화/중간 시작에 입장·나침반 이력을 강제하지 않는다. 나침반은 실제 표시될 때만 누른다.

`screen_stage` / `screen_action`이 최신 판단 함수다. 소스의 `ALLOWED` 상수는 이전 구현의 잔재이며 현재 행동 결정을 제한하는 데 쓰지 않는다. 이 상수로 예전 순차 의존성을 복원하면 안 된다.

현재 우선순위:
1. 준비 취소 → 아무 입력 없음.
2. 도전 확인창 → 제목+버튼 검증 후 도전하기.
3. 준비 완료.
4. 던전 목록 → 2~3인 모드의 지정 던전만.
5. 결과 화면 → 파티별 경로.
6. 클리어 터치, 장면 넘기기, 입장하기, 나침반.

게임 조작 HUD(PC ASSIST 텍스트)는 전투 단계 복구 보조 단서다. HUD는 마을에도 있을 수 있으므로 '보스 전투 중임이 증명됐다'고 해석하지 말 것. 명확한 팝업/결과 화면이 HUD보다 우선한다.

## 5. 완료 횟수 집계

결과 화면(다시 하기 또는 다른 던전 가기)을 2회 연속 확인하면 1회 집계한다. 준비 완료/취소 또는 도전 확인창이 겹친 화면은 결과 집계에서 제외한다. 동일 결과에서 여러 프레임/재시도 대기/준비 대기를 하더라도 한 번만 센다. 다음 게임 HUD/나침반/브레이크/연출을 확인해야 다음 완료를 세도록 재무장한다.

완료 횟수 1 = 첫 결과 화면에서 정지, 재입장 버튼은 누르지 않음. N = 총 N회 완료. 0 = 무제한(오류/타임아웃 정지는 유지). 4인 파티원도 결과에서 세고 파티장의 요청을 기다린다. 결과 화면 중간에서 처음 켜면 그 결과를 첫 완료로 세므로 횟수1에서는 정지한다.

## 6. 음식 선택 기능

- 기본 꺼짐. 켜면 음식 바로 먹기 버튼이 나타날 때만 먹는다. 매 판 강제로 먹지 않는다.
- 포만감 기준은 게임 내 '음식 바로 먹기 버튼 표시' 설정에 맡긴다. 사용자는 예시로 포만감50%를 보여줬다. 앱에서 그 숫자를 강제하지 않는다.
- PC는 왼쪽 위 B 표시를 인식해 B 입력. Android는 B 표시가 없을 수 있어 음식 아이콘/버튼 자체를 모바일 화면에서 확인해야 한다.
- PC는 2회 연속 감지, 한 번 입력 후 사라졌다 재등장해야 재입력, 최소 10초 간격. 4회 연속 미감지 시 사라짐으로 판정.
- 실제 음식 소비, 잔여 수량, 버프 유무는 판단하지 않는다. 게임에서 음식을 준비해야 한다.

## 7. 브레이크 선택 기능

- 기본 꺼짐. '브레이크 / 브레이크 익스텐드' 큰 문구 감지 시 6번 스킬 사용.
- 같은 표시가 떠 있는 동안 중복하지 않고, 2회 미감지로 재무장, 입력 사이 최소 2초. 인식 기준 미달·불명확하면 누르지 않는다.
- PC는 키보드 상단6을 0.12초 누른다. Android는 해당 스킬 버튼 터치로 바꿔야 하며 모바일 배치 확인 필요.
- 쿨타임, 자원/충전 부족, 발동 성공은 판단하지 않는다. 입력 기록은 실제 발동 증거가 아니다.
- 기존 큰 창 템플릿은 작은 창에서 점수가 약0.81로 기준0.84에 못 미쳐 입력이 없었다. 작은 창 템플릿 추가 후 별도 인접 프레임에서 약0.97 확인. 큰 글씨가 이펙트/데미지 숫자에 가려져도 항상 감지된다는 뜻은 아니다.
- 일반 브레이크 단독 연출은 익스텐드보다 검증이 부족하다. 공통 큰 '브레이크' 글자를 보며, 독립 연출 자료를 추가 검증할 것.

## 8. 입력·타이밍·중복 방지

- 화면 검사 간격 PC 350ms + 실제 이미지 분석 시간. 모든 행동은 고정 영상 시간 예약이 아닌 화면 감지 방식.
- 보통 행동은 동일 대상을 2회 연속 확인하고 실행한다. 클리어 문구에서도 몇 초 고정 대기는 없다.
- 입력 후 1.2초 다음 입력 대기. 키/마우스 누름0.12초, 마우스 위치 이동 후0.06초.
- 입력한 대상이 사라지기 전 같은 행동을 반복하지 않는다. 30초간 같은 대상이 계속 인식되면 전환 실패로 정지한다. 예전12초는 폐기됨.
- 30초는 로딩/매칭 전체 제한이 아니다. 준비 취소나 다음 화면으로 바뀌면 해당 단계로 이어간다.
- 버튼 활성/비활성 밝기 구분은 아직 미구현. 비활성 버튼도 텍스트가 같으면 감지되어 30초 후 정지할 수 있다.
- 진행 타임아웃 기본15분, 오류 시 정지. 중간에 잘못된 창을 조작하거나 아무 팝업이나 닫지 않는다.
- PC는 실제 실행 전 활성 창/마우스 위치의 창 소유권 확인. Android도 게임 외 앱에 잘못 터치하지 않도록 별도 대상·전환 검사 필요.

## 9. 이미지 인식과 크기 변경

PC 클라이언트만 잘라 1660×1024로 정규화. OpenCV TM_CCOEFF_NORMED, 기본 기준0.84. 각 템플릿 ROI는 assets/templates/config.json. 브레이크/나침반은 밝기210 이진화, 나침반 회전15도 간격. 여러 크기와 가로세로 비율을 비교하고 작은 원본의 흐려짐에 맞춰 템플릿도 축소 후 복원한다. 크기별 템플릿 계산은 캐시한다.

크기 변경 시 이전 감지 결과를 버리고 마지막 크기 변경 후 약1초 안정화를 기다린다. 그 뒤 새 좌표로만 입력한다. 크기 변경 중 pending 전환 타이머도 갱신한다.

원본/640×400/480×300/320×200 영상56개 검사에서55개 기대 동작 일치, 320×200의 장면 넘기기1개 미감지. 오감지된 다른 버튼은 이 표본에서 없었다. 실제 게임 창은 크기에 따라 UI 재배치가 일어나므로 영상 축소 검사가 실제 모든 해상도의 성공을 보장하지 않는다. 최소 크기에서 무조건 인식된다고 약속하지 않는다.

Android의 상태/내비게이션 바, 노치, 가로 방향, 화면 배율, 게임 UI 재배치 및 키보드 오버레이를 반영해야 한다. PC 템플릿/좌표는 참고이지 모바일 실측값이 아니다.

## 10. UI와 아이콘 선호

이름은 '끌림 매크로'. 큰 한글 글씨, 청색 중심, 눈에 띄는 시작·정지 안내.
순서: 1 실행 모드(인식만 확인 / 실제 실행) 바로 아래 미리보기 → 2 인원/역할/대상 던전 및 음식/스킬 옵션 → 3 반복 설정. 시작/일시정지/즉시정지에 항상 접근 가능해야 한다.

켜짐은 파란 체크와 '사용 중', 꺼짐은 빈 칸과 '사용 안 함'. X 표시 금지. 인식 확인은 첫 사용 시 권장하는 선택 사항, 매번 또는 처음에 강제하지 않는다. PC 기본 모드는 인식만 확인이며 기능 옵션은 모두 꺼짐.

메인 화면에 로그 경로 설명은 표시하지 않는다. 내부 진단 로그는 가능. 아이콘은 제공 캐릭터 이미지에서 노란100 배지를 제거한 assets/icon.png.

## 11. PC 전용 사항을 모바일에 옮기지 말 것

PC는 게임이 관리자 권한일 때 매크로도 관리자 권한이어야 입력이 전달됐다. PC는 맨 앞 게임에만 입력하며 다른 창을 클릭하면 대기한다. 비활성 게임 입력/완전 백그라운드 조작은 미구현이다. 유튜브와 나란히 시청은 가능하나 유튜브 조작 중 계속 게임에 입력하는 기능을 구현했다고 말하면 안 된다.

Android는 사용자 승인 화면 캡처와 접근성 기반 터치를 검토하되 기존 Android 채팅의 실제 구현·권한·기기 검증을 따를 것. 루팅, 보안 우회, 메모리 조작, 계정 정보 수집은 이 요구사항에 없다. 화면 캡처/접근성 권한을 사용자가 직접 승인해야 하고 실제 게임에서 차단되면 정확히 보고한다. PC F8/F9 대신 Android용 시작/일시정지/즉시정지 UI가 필요하다.

## 12. 검증 범위를 구분할 것

실제 사용자 확인: 초기 PC 입력은 관리자 권한 실행 후 동작. 이후 사용자가 반복 테스트 영상을 제공해 미감지/진행 상태 버그가 발견됐다.

최신 검증: 영상 인식, 모의 키/마우스 입력(게임에 실제 보내지 않음), EXE 초기화 및 UI 체크 상태 전환. v0.12의 2~3인 목록 재입장, 1인/4인 파티장 다시 하기, 4인 파티원 대기→준비 완료→취소 방지, 완료 횟수 중복 방지, 중간 시작, 크기 변경 검사를 통과했다.

미확인: v0.12 모든 실제 파티 조합의 연속 전체 게임 실행, 모든 옵션 동시 실행, 모바일 화면/터치, 모든 해상도, 스킬 발동 성공. mock검사 통과를 실기 검증으로 표현하지 않는다.

## 13. 낚시 후속 단계

집중 낚시 문구로 선별하고 게이지 방향/찬스 타이밍에 맞춰 당기려는 구상이다. 선별 기준은 사용자가 정하기로 했고, PC 채팅에서는 아직 낚시 진행 영상을 받지 않았다. 공략상 '묵직한 느낌이 전해진다 / 예감이 좋다 / 찌가 흔들렸다 / 입질이 왔다 / 반응이 왔다 / 뭔가 걸렸다'를 조사했으나 최신 실제 판정은 검증하지 않았다. 낚시 완성으로 주장하거나 임의 기준을 확정하지 않는다.

## 14. 전달받은 채팅에서 할 일

기존 Android 구현을 먼저 확인하고 최신 파티별 경로, 준비 취소 금지, 중간 시작 복구, 완료 횟수 latch,30초 대기를 대조한다. Kotlin 등 현재 언어로 상태 판단을 옮기되 Windows 입력 코드는 실행하지 않는다. 다음 자료는 모바일 게임의 버튼·음식·스킬6·준비 창·인원부족 확인창·결과·던전 목록 영상/스크린샷이다. 이미 다른 채팅에서 확보했다면 재요청하지 않는다.

현재 저장소 main의 파일 또는 이 패키지를 참고한다. 작업 중 로컬 변경은 보존하고 git reset/강제 덮어쓰기를 하지 않는다. 동영상 원본/사용자 로그는 이 전달 패키지에 없으며 로컬 PC 경로를 클라우드에서 열 수 있다고 가정하지 않는다.
